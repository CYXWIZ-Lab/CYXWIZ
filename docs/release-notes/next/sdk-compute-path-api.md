The plugin SDK's neural provider headers have new public API for the compute path. `cyxwiz/neural_provider.h`: `ScopedNeuralRunTarget` (the device a run bound is the provider target of every request made in the scope), `BoundNeuralRunTarget` and `QueryArrayFireNeuralTarget`. `cyxwiz/neural_provider_dispatch.h`: the dispatch outcome `NeuralDispatchOutcome::NotServed` (no provider serves the device family, or the request is off the run's bound device; reported once per layer, operation, device family and cause in an observer's scope), `NeuralDispatchTally` (what ran where, counted per layer, operation and device family; `Find` takes the device) and `CheckNeuralRunTarget`. `cyxwiz/rl/ppo.h`: `ScopedPpoProviderRun`, the per-run latch of PPO's provider kernels. `cyxwiz/backend_fallback_reason.h`: the reasons `provider_not_built`, `provider_not_installed`, `provider_abi_mismatch`, `provider_disabled`, `provider_not_offered`, `target_mismatch` and `provider_latched` (a provider this run turned off after a failure). A plugin that switches exhaustively over `BackendFallbackReason` or `NeuralDispatchOutcome` sees `-Wswitch` warnings (an error with warnings as errors) until it handles the new values or adds a `default`. Policy playback and the stress test now follow the Strict execution policy as training does: under Strict a provider failure stops them, naming the provider and the operation, instead of falling back to ArrayFire.
