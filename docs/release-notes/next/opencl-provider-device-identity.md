The OpenCL provider now finds the GPU a run chose by the device itself, not by its position in a list. ArrayFire and the provider order OpenCL devices differently on a computer with GPUs of several vendors, so a recurrent layer could run on another GPU than the one chosen in Preferences > Devices. It matches the device by its handle, then by its PCI address or UUID, then by its name and vendor (a driver that reaches the GPU through another OpenCL loader no longer has it declined for the rest of the session), and by position only where nothing else can tell: when ArrayFire's device handle cannot be read, or for identical GPUs that report no PCI address or UUID. The log then warns that which physical GPU runs the layer is uncertain. A device that matches none of the provider's GPUs, or whose type ArrayFire cannot report and whose name matches none, is declined with the reason, and the layer computes on ArrayFire on the same device. An OpenCL CPU device is now declined with that reason.
