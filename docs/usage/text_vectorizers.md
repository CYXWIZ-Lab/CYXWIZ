# Text Vectorizer Nodes

CyxWiz provides dense TF-IDF and count-vectorizer nodes for classic NLP
workflows. Their numerical contract follows scikit-learn for raw counts, IDF,
binary presence, vocabulary capping, and optional row normalization on the
supported tokenization subset.

## TFIDFVectorizer

`TFIDFVectorizer` computes raw term count multiplied by optional IDF, then
applies the selected row normalization:

```text
norm=none  count * idf
norm=l1    l1_normalize(count * idf)
norm=l2    l2_normalize(count * idf)
```

Important properties:

```text
text_col       required text column
label_col      optional label column copied to y
max_features   dense output width cap
min_df         minimum document frequency
ngram_range    1,1 | 1,2 | 1,3 | 2,2 | 2,3 | 3,3
stop_words     english | none
norm           l1 | l2 | none
use_idf        true | false
smooth_idf     true | false
output_format  dense
```

With smoothed IDF, the weight is:

```text
log((1 + document_count) / (1 + document_frequency)) + 1
```

## CountVectorizer

`CountVectorizer` emits raw term counts before optional normalization. This is
different from dividing every count by the number of tokens in the document.

```text
binary=false, norm=none  raw integer-valued counts in float32 columns
binary=true,  norm=none  0/1 term-presence values
norm=l1 or l2            normalize the count or presence row afterward
```

Important properties:

```text
text_col       required text column
label_col      optional label column copied to y
max_features   dense output width cap
ngram_range    1,1 | 1,2 | 1,3 | 2,2 | 2,3 | 3,3
stop_words     english | none
norm           l1 | l2 | none
binary         true | false
output_format  dense
```

Both vectorizers keep the most frequent terms when `max_features` caps the
vocabulary, with deterministic tie-breaking and alphabetical output order.

## N-grams and stop words

The generic Properties panel exposes the canonical `ngram_range` control.
Older saved graphs containing `ngram_min` and `ngram_max` still load when
`ngram_range` is absent, but those aliases are intentionally not separate GUI
properties. When both forms exist, `ngram_range` wins.

Examples:

```text
1,1  unigrams only: good
1,2  unigrams and bigrams: good, not good
2,2  bigrams only: not good
1,3  unigrams through trigrams: good, very good, not very good
```

Malformed, zero, negative, reversed, or unsupported ranges fail before
materialization. The current maximum n-gram width is three.

English stop words are removed before n-grams are generated. For sentiment
classification, prefer:

```text
ngram_range=1,2
stop_words=none
```

The engine's English stop-word list includes negation words such as `not` and
`no`; keeping them allows phrase features such as `not good` and `no hope`.

## TextTokenizer

Use `TextTokenizer` instead when the downstream model expects token IDs, such
as an Embedding, recurrent, attention, or transformer path. TF-IDF and count
features are dense float columns, not token sequences.

## Dense output and memory safety

The executable vectorizer contract is currently:

```text
output_format=dense
```

Raw output size is approximately:

```text
rows * selected_features * 4 bytes
```

Peak materialization is higher because token maps, vocabulary statistics,
Arrow builders, labels, and training batches also consume memory. Compiler and
runtime preflight report the estimate, and the operator blocks before heavy
tokenization/allocation when the configured or available-memory limit would be
exceeded.

Sparse output is deliberately rejected rather than silently materialized as
dense. The real sparse storage, batching, tensor, and first-layer path is
tracked by `internal/repository-private/engineering/Data Studio/tofix45.md`.

## Fitted state

Fit/transform workflows may save the selected vocabulary and TF-IDF weights as
a `.cyxstate.json` artifact. `Transform Only` keeps the fitted column order and
width, rejects incompatible node settings, and emits zero values for unknown
terms. New artifacts pin `value_semantics=sklearn_raw_count_v1`; refit older
vectorizer states rather than silently reusing pre-parity count semantics.

Computation-truth fixtures are generated by scikit-learn 1.8 and checked by
`test_computation_truth_text_vectorizers`.
